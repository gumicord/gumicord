## この文書の読み方

### 要件 ID

| 接頭辞 | 領域 |
|---|---|
| `FR-` | 機能要件 — クライアント本体の振る舞い |
| `EXT-` | 拡張性要件 — テーマ / プラグイン / UITree ABI |
| `NFR-` | 非機能要件 — 性能・品質・信頼性 |
| `PLT-` | プラットフォーム統合要件 — OS 固有の振る舞い |
| `SEC-` | セキュリティ・プライバシー要件 |

ID は**永久欠番制**。要件を削除しても ID は再利用せず、`廃止` としてマークする。
実装のコミットメッセージ・PR・テスト名は該当する要件 ID を必ず参照する。

### 記法

EARS (Easy Approach to Requirements Syntax) に準拠する。

| 型 | 書式 |
|---|---|
| 常時 | システムは **〜しなければならない** |
| イベント駆動 | **〜したとき**、システムは 〜しなければならない |
| 状態駆動 | **〜である間**、システムは 〜しなければならない |
| 条件付き | **〜の場合**、システムは 〜しなければならない |
| 異常系 | **もし 〜ならば**、システムは 〜しなければならない |

### マイルストーン列

| 記号 | 意味 |
|---|---|
| **M1** | 最初の動作するクライアント。拡張基盤を含む |
| **M2** | 実用に耐えるクライアント |
| **M3** | 音声・映像 |
| **M4** | 以降 |

## EXT — 拡張性要件

> **この節が本プロジェクトの存在理由である。** 他の要件と衝突した場合、原則として EXT を優先する。

### UITree (拡張 ABI)

| ID | 要件 | M |
|---|---|---|
| `EXT-001` | システムは、UI をセマンティックノードのツリー (UITree) として構築しなければならない | M1 |
| `EXT-002` | UITree の各ノードは、`spec/03-uitree.md` に列挙された**安定 ID** を持たなければならない | M1 |
| `EXT-003` | システムは、メジャーバージョン内で安定 ID に破壊的変更を加えてはならない。ノードの追加のみを許す | M1 |
| `EXT-004` | 安定 ID を削除または改名する必要が生じた場合、システムは 1 メジャーバージョン以上の非推奨期間を設けなければならない | M1 |
| `EXT-005` | システムは、UITree を全プラットフォームで同一の実装から構築しなければならない | M1 |
| `EXT-006` | システムは、開発者向けに UITree を実行時に可視化する検査ツール (UITree Inspector) を提供しなければならない | M2 |

### テーマ

|---|---|---|
| `EXT-010` | システムは、テーマを JSON として読み込まなければならない | M1 |

| `EXT-014` | テーマは、条件 (ライト/ダークモード・プラットフォーム・ウィンドウ幅) ごとにスタイルを分岐できなければならない | M1 |
| `EXT-015` | システムは、テーマファイルの変更を検知して再起動なしに再適用しなければならない | M1 |
| `EXT-016` | もしテーマが JSON Schema に違反するならば、システムは該当ルールのみを無視し、エラーを利用者に提示した上で残りを適用しなければならない | M1 |
| `EXT-017` | テーマは、フォントと画像アセットを同梱できなければならない | M2 |
| `EXT-018` | テーマは、ノードのレイアウト (方向・配置・サイズ制約・表示/非表示) を上書きできなければならない | M2 |
| `EXT-019` | システムは、複数テーマの適用順序と合成を定義しなければならない | M2 |
| `EXT-020` | システムは、全プラットフォームで同一のテーマ JSON に対し同一の描画結果を生成しなければならない | M1 |

### 拡張の安全弁

| ID | 要件 | M |
|---|---|---|
| `EXT-050` | もしプラグインが例外を送出したならば、システムはそのプラグインのみを隔離し、クライアント本体の動作を継続しなければならない | M1 |
| `EXT-051` | もしプラグインが規定時間内に処理を完了しないならば、システムはその実行を中断し、利用者に通知しなければならない | M1 |
| `EXT-052` | システムは、全プラグインを一時無効化して起動する「セーフモード」を提供しなければならない | M1 |
| `EXT-053` | システムは、プラグインごとの CPU 時間とメモリ使用量を計測し、利用者に提示しなければならない | M2 |

## NFR — 非機能要件

### 性能

数値は**スパイクでの実測後に確定する** ([08-spike-plan.md](08-spike-plan.md))。現時点の値は目標であり、根拠は ADR に記録する。

| ID | 要件 | M |
|---|---|---|
| `NFR-001` | システムは、コールドスタートから操作可能になるまでの時間が 1000ms を超えてはならない (デスクトップ, 実測基準は要スパイク) | M1 |
| `NFR-002` | システムは、アイドル時の常駐メモリが 250MB を超えてはならない (デスクトップ, 要スパイク) | M1 |
| `NFR-003` | システムは、スクロール中にディスプレイのリフレッシュレートに追従し、フレーム落ちを起こしてはならない | M1 |
| `NFR-004` | システムは、120Hz 以上の可変リフレッシュレートに対応しなければならない | M1 |
| `NFR-005` | ウィンドウが非アクティブである間、システムは描画を停止し CPU 使用率を最小化しなければならない | M1 |
| `NFR-006` | システムは、メッセージ入力から画面反映までの遅延が 16ms を超えてはならない | M1 |
| `NFR-007` | システムは、10 万件規模のメッセージ履歴に対しても一定のスクロール性能を維持しなければならない (仮想化) | M2 |

### 品質・信頼性

| ID | 要件 | M |
|---|---|---|
| `NFR-010` | システムは、ネットワーク切断時に自動再接続と取りこぼしたイベントの再同期を行わなければならない | M1 |
| `NFR-011` | オフラインである間、システムはローカルキャッシュから履歴を表示しなければならない | M2 |
| `NFR-012` | オフライン中に送信されたメッセージは、システムがキューイングし再接続時に送信しなければならない | M2 |
| `NFR-013` | もしクラッシュしたならば、システムは次回起動時に前回の状態 (開いていたチャンネル・下書き) を復元しなければならない | M2 |
| `NFR-014` | システムは、テーマ・プラグイン・UITree の各仕様に対する適合テストスイートを持たなければならない | M1 |
| `NFR-015` | システムは、全プラットフォームで同一の UITree・テーマから生成された描画結果をスクリーンショット比較で検証しなければならない | M1 |

| `SEC-003` | システムは、利用者の明示的な同意なしにいかなるテレメトリも送信してはならない | M1 |

| `SEC-010` | プラグインは、manifest で宣言したケイパビリティの範囲でのみ動作しなければならない | M1 |
| `SEC-011` | プラグインのインストール時、システムは要求されたケイパビリティを利用者に提示し、承認を得なければならない | M1 |
| `SEC-012` | プラグインが未宣言のケイパビリティを使用しようとした場合、システムは当該呼び出しを拒否し記録しなければならない | M1 |
| `SEC-013` | プラグインは、ネットワーク通信先を manifest でホスト単位に宣言しなければならない | M2 |
| `SEC-014` | プラグインのストレージは、プラグインごとに分離されなければならない | M1 |
| `SEC-015` | システムは、プラグインからネイティブコードの読み込みおよび任意コマンドの実行を許してはならない | M1 |
| `SEC-016` | レジストリ経由で配布されるプラグインは、署名を検証されなければならない | M4 |
| `SEC-020` | システムは、ローカルキャッシュのデータベースを暗号化しなければならない | M2 |
| `SEC-021` | システムは、ログアウト時にローカルキャッシュと認証情報を完全に削除しなければならない | M1 |
