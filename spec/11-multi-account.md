# 複数アカウント（簡易版）

## 目的

ユーザーアカウントとbotアカウントを複数保存し、ログアウトして認証情報を
再入力することなく切り替えられるようにする。実装はM1の簡易版とし、
アカウント管理専用画面は作らず、ログイン後のユーザーメニューから操作する。

## 保存

- トークン本体は既存の `SecretStore` に暗号化して保存する。
- 保存キーはアカウントIDを含む不透明なキーにする。例:
  `account_user_<id>` / `account_bot_<id>`。
- アカウントIDは、ログイン成功時の `GET /users/@me` の結果から得る。
- 既存の `token` と `bot_token` は後方互換のため読み取り、成功後に
  アカウント別キーへ移行する。
- botとユーザーは認証種別を別情報として保持する。同じIDを別種別で保存しない。
- トークンを一覧やUIデータ、ログ、キャッシュに含めない。

## アカウント一覧と切り替え

- ユーザーパネルのメニューに「アカウントを切り替え」と
  「アカウントを追加」を追加する。
- 一覧には表示名とアカウントIDの末尾だけを表示し、トークンは表示しない。
- 現在のアカウントにはチェック状態を付ける。
- アカウント切り替え時は、現在のGatewayとRESTの処理を停止し、現在の
  `Live` を破棄してから、選択したトークンでログイン済み状態を再構築する。
- 切り替えに失敗した場合は現在のアカウントへ戻さず、選択先だけを失敗扱いにする。
  現在の接続を先に壊さない実装が望ましい。
- 「アカウントを追加」はログイン画面へ戻り、成功したアカウントを一覧へ追加する。

## アカウント別キャッシュ

- SQLiteファイルをアカウントIDごとに分ける。
  例: `cache/accounts/user_<id>.db` と `cache/accounts/bot_<id>.db`。
- `Live` はログイン成功時に該当アカウントのDBを開く。
- アカウント切り替え時は、前のDBのwriter threadを停止してから次のDBを開く。
- guild、channel、message、member、既読状態、最後に開いたchannelを混在させない。
- 未ログイン時に表示するキャッシュは持たない。表示する場合は現在選択中の
  アカウントのキャッシュだけに限定する。
- ログアウトは現在のアカウントのキャッシュを削除する。保存済みアカウントを
  残す操作は「このアカウントを削除」と分ける。

## botとの差分

- botはbot REST認証とbot Gateway identifyを使う。
- botのメンバー一覧は `GUILD_MEMBERS` intent と OP 8で取得する。
- ユーザー専用の既読APIやユーザー用member-list購読はbotでは実行しない。
- アカウント切り替え後もTokenKind、RESTヘッダー、Gateway intentを同じアカウントの
  情報から再構築する。

## botメンバー一覧の組み立て

OP 8の応答はチャンク分割で見出しを持たないため、表示用の並びは
クライアント側で作る。公式クライアントのユーザー向け一覧と同じ見た目にする。

- 要求は `query: ""` / `limit: 0`（無制限）/ `presences: true` で送る。
  毎フレーム送るとセッションごとの回数制限に当たり、大きいサーバーほど
  欠けた名簿で止まる。READYより前に送っても捨てられるため、接続確立後の
  1回を基本とし、未完了のまま30秒経った要求だけ送り直す。再接続で応答が
  失われた可能性があるときも送り直す（重複はユーザーID基準で吸収する）。
- チャンクは到着順にユーザーID基準で蓄積し、順不同・重複を吸収する。
  オフセット計算で結合しない。
- 見出しはギルドのロールから作る。hoistされたロールをpositionの降順、
  続けてオンライン、最後にオフライン。オフラインの人はロールに関わらず
  オフラインにまとめる。空の見出しは出さない。
- 在席はチャンク内の `presences` を使い、無い人はオフライン扱い。
  人数は蓄積した実数（見出しごとの実数と全体の実数）を出す。
- ロールがチャンクより後に届いたら、持っている名簿を組み立て直す。

## 受け入れ条件

1. Aでログインした後、Bを追加できる。
2. AからBへ切り替えると、Bのguild・channel・messageだけが表示される。
3. BからAへ戻すと、Aのキャッシュと最後のchannelが復元される。
4. botアカウントとユーザーアカウントを保存しても、認証ヘッダーが混ざらない。
5. 保存済みアカウントのトークンはログ・UI・SQLiteに現れない。
6. 既存の単一トークン保存から移行できる。

## 簡易版で対象外

- 同一アカウントの複数セッション同期
- アカウント名の編集、並べ替え、エクスポート
- アカウントごとの通知設定UI
- 自動ログインする既定アカウントの複雑な選択ルール
