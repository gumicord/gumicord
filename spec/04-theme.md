## 1. 設計方針

テーマは **JSON** で書く (`EXT-010`)。CSS を採用しない理由は 3 つ。

1. **CSS パーサとカスケード規則を自前で実装するのは、JSON を読むより桁違いに重い**
2. **CSS の詳細度 (specificity) は予測が難しい。** 拡張 ABI の一部として、テーマ作者が結果を予測できることを優先する
3. JSON Schema による検証・エディタ補完・CI 検査がそのまま使える

テーマが介入できるのは [03-uitree.md](03-uitree.md) が定める**安定 ID を持つノードのみ**である。

```
theme.json ──[JSON Schema 検証]──▶ トークン表 + ルール表
                                        │
                                  [セレクタ索引化]
                                        │
                      UITree の各ノードに対して照合し、スタイルを確定
```

## 2. ファイルの構造

```jsonc
{
  "$schema": "https://gumicord.dev/schema/theme-1.json",

  "manifest": {
    "id": "com.example.midnight",
    "name": "Midnight",
    "version": "1.0.0",
    "author": "ねんねこ",
    "description": "深い紫の夜",
    "abi": 1
  },

  "tokens": {
    "color.bg.base":      "#0f0f17",
    "color.bg.raised":    "#16161f",
    "color.bg.hover":     "#ffffff14",
    "color.text.primary": "#eaeaf0",
    "color.text.muted":   "#8a8a9a",
    "color.accent":       "#7c6cf0",

    "radius.sm": 4,
    "radius.md": 8,
    "radius.full": 9999,

    "space.1": 4,
    "space.2": 8,
    "space.3": 16,

    "font.body":  { "family": "Inter", "size": 15, "lineHeight": 22 },
    "font.title": { "family": "Inter", "size": 16, "lineHeight": 22, "weight": 600 }
  },

  "rules": [
    {
      "select": "app.window",
      "style": { "background": "$color.bg.base", "color": "$color.text.primary" }
    },
    {
      "select": "chat.message",
      "when": { "state": "hover" },
      "style": { "background": "$color.bg.hover" }
    },
    {
      "select": "chat.message.header.author",
      "style": { "font": "$font.title", "color": "$color.accent" }
    },
    {
      "select": "nav.guild_list.item",
      "when": { "platform": "mobile" },
      "style": { "width": 40, "height": 40, "radius": "$radius.full" }
    }
  ]
}
```

### 2.1 `manifest.abi`

テーマが想定する UITree の ABI メジャーバージョン。**必須。**

クライアントの ABI より大きい値なら「このテーマは新しすぎる」と利用者に伝え、既知のルールのみを適用する。小さい値なら通常どおり適用する ([4 章](#4-前方互換性と後方互換性))。

## 3. デザイントークン (`EXT-011`)

### 3.1 命名

ドット区切り。**カテゴリ.用途.変種** の順。

| カテゴリ | 例 | 値の型 |
|---|---|---|
| `color.*` | `color.bg.base`, `color.accent` | 色 |
| `radius.*` | `radius.md` | 数値 (論理 px) |
| `space.*` | `space.2` | 数値 (論理 px) |
| `font.*` | `font.body` | フォント定義 |
| `shadow.*` | `shadow.raised` | 影定義 |
| `motion.*` | `motion.fast` | 数値 (ミリ秒) |

**トークン名は自由に定義できる。** クライアントが決まった名前を要求することはない。テーマ作者が自分の語彙を作る場所である。

ただし**公式テーマの語彙を推奨語彙として提示する**。プラグインが `$color.accent` を参照したいとき、共通の名前があると噛み合うためである ([3.4](#34-プラグインとの共有語彙))。

### 3.2 参照

`$` 接頭辞でトークンを参照する。

```jsonc
{ "background": "$color.bg.raised" }
```

トークンは**他のトークンを参照できる**。循環参照は検証時に検出してエラーにする。

```jsonc
{
  "color.brand": "#7c6cf0",
  "color.accent": "$color.brand"
}
```

### 3.3 値の型

| 型 | 書式 | 例 |
|---|---|---|
| 色 | `#RGB` / `#RRGGBB` / `#RRGGBBAA` | `"#7c6cf0"`, `"#ffffff14"` |
| 長さ | 数値 (論理 px)。DPI スケールは自動で掛かる | `8` |
| フォント | オブジェクト | `{ "family": "Inter", "size": 15, "lineHeight": 22, "weight": 600 }` |
| 影 | オブジェクト | `{ "x": 0, "y": 2, "blur": 8, "color": "#00000040" }` |
| 時間 | 数値 (ミリ秒) | `150` |

**長さは常に論理ピクセルで指定する。** 物理ピクセルへの変換はレンダラが行う (`PLT-009`)。

### 3.4 プラグインとの共有語彙

プラグインが生成したノードも、テーマの適用対象になる ([02-architecture.md のパイプライン](02-architecture.md#フレームのパイプライン-) [4] → [5])。

プラグインが `primitive.badge` を挿入すれば、テーマの `primitive.badge` ルールが自動的に当たる。**プラグイン作者がテーマを意識しなくても、見た目が浮かない。** これが `primitive.*` を安定 ID に含めた理由である。

## 4. セレクタと条件

### 4.1 `select` — 安定 ID による照合

```jsonc
{ "select": "chat.message.header.author", "style": { /* ... */ } }
```

**完全一致のみ。** ワイルドカードも子孫セレクタも M1 では提供しない。

> **なぜワイルドカードを入れないか**
>
> `chat.message.*` のようなパターンを許すと、安定 ID を**追加**したときに既存のテーマの見た目が変わる。
> つまり「追加は破壊的変更ではない」という [03-uitree.md の C3](03-uitree.md#4-後方互換性の規則-ext-003-ext-004) が成立しなくなる。
>
> 前方互換性とワイルドカードは両立しない。**前方互換性を採る。**

### 4.2 `when` — 条件分岐 (`EXT-013`, `EXT-014`)

すべての条件が成立したときだけルールが適用される。

```jsonc
{
  "select": "nav.channel_list.item",
  "when": { "state": ["hover", "unread"], "colorScheme": "dark" },
  "style": { /* ... */ }
}
```

| キー | 値 | 意味 |
|---|---|---|
| `state` | 状態名、またはその配列 | 配列は **AND** — すべて成立が必要 (`EXT-013`) |
| `platform` | `windows` / `macos` / `linux` / `android` / `ios` / `desktop` / `mobile`、またはその配列 | 配列は **OR** — いずれか成立で可 (`EXT-014`) |
| `colorScheme` | `light` / `dark` | OS 設定に追従 (`PLT-005`) |
| `minWidth` | 数値 (論理 px) | ウィンドウ幅がこれ以上 (境界を含む) |
| `maxWidth` | 数値 (論理 px) | ウィンドウ幅がこれ以下 (境界を含む) |
| `slot` | 文字列 | 同じ安定 ID を、位置で区別する |

状態の一覧は [03-uitree.md 2.3](03-uitree.md#23-状態-states) が定義する。

> **`slot` はスノーフレークには一致しない。**
>
> `key` には `Id` (スノーフレーク) と `Slot` (位置) と `Index` (連番) がある。
> このうちテーマから見えるのは `Slot` だけである。
>
> `Id` に一致してしまうと、テーマが「このサーバだけ赤くする」と書けることになる。
> **テーマが利用者のデータに依存し、他人に配れるものではなくなる。** 飾りたい相手が誰かも漏れる。
> `Index` は並びが変われば別のものを指すので、飾り分ける意味がない。
>
> ```json
> { "select": "nav.user_panel.presence", "when": { "slot": "dnd" },
>   "style": { "background": "#e05260" } }
> ```

> **配列の意味が `state` と `platform` で逆なのは意図的である。**
>
> 状態は同時に複数立ちうるので、`["hover", "unread"]` は「両方」以外に意味を持たない。
> プラットフォームは同時に 1 つしか成立しないので、`["android", "ios"]` は「どちらか」以外に意味を持たない。
> **どちらも「その書き方に意味がある唯一の解釈」を採っている。**

`when` の**キーどうし**は常に AND である。`{ "state": "hover", "colorScheme": "dark" }` は両方成立が必要。

### 4.3 未知の条件はルールごと無視する

`when` に未知のキー・未知の状態名・未知のプラットフォーム名があった場合、**そのルール全体を無視する**（警告）。

条件だけを落として適用すると、テーマ作者が意図したより**広い範囲にスタイルが当たる**。無視するほうが安全側に倒れる。

## 5. カスケード規則

> **CSS の詳細度を採用しない。規則は 1 つだけである。**

| # | 規則 |
|---|---|
| **K1** | **ルールは記述順に適用される。後のルールが前のルールを上書きする。** |

セレクタの「具体性」を計算しない。`when` の数も考慮しない。**書いた順がすべて。**

```jsonc
"rules": [
  { "select": "chat.message", "style": { "background": "#111" } },
  { "select": "chat.message", "when": { "state": "hover" }, "style": { "background": "#222" } }
]
// hover 中は #222。順序を逆にすると hover が効かなくなる。
```

**これは不便に見えるが、意図的である。** テーマ作者が「なぜこのルールが効かないのか」を調べるとき、上から読めば必ず分かる。CSS の詳細度で数時間溶かす体験を持ち込まない。

### 5.1 上書きの単位はプロパティ

ルール全体ではなく**プロパティ単位**で上書きする。

```jsonc
{ "select": "chat.message", "style": { "background": "#111", "radius": 8 } },
{ "select": "chat.message", "style": { "background": "#222" } }
// 結果: background=#222, radius=8
```

### 5.2 テーマとプラグインの優先順位

**プラグインがテーマより後に適用される。衝突したらプラグインが勝つ** ([02-architecture.md](02-architecture.md#この順序の根拠))。

```
[5] テーマ解決  →  [6] プラグインのスタイル介入
```

### 5.3 複数テーマの合成 (`EXT-019`)

**M2 で定義する。** M1 では 1 度に 1 つのテーマのみを適用する。

## 6. スタイルプロパティ (M1)

| プロパティ | 型 | 意味 |
|---|---|---|
| `background` | 色、または**背景オブジェクト** ([6.1](#61-背景画像-ext-021-ext-024)) | 背景 |
| `color` | 色 | 前景 (文字色)。子に継承する |
| `font` | フォント | 書体。子に継承する |
| `borderColor` | 色 | 枠線 |
| `borderWidth` | 長さ | 枠線の太さ |
| `radius` | 長さ | 角丸 |
| `padding` | 長さ、または `[上, 右, 下, 左]` | 内余白 |
| `margin` | 長さ、または `[上, 右, 下, 左]` | 外余白 |
| `gap` | 長さ | 子どうしの間隔 |
| `width` / `height` | 長さ | 大きさ |
| `minWidth` / `maxWidth` | 長さ | 大きさの制約 |
| `minHeight` / `maxHeight` | 長さ | 同上 |
| `opacity` | 0.0〜1.0 | 不透明度 |
| `shadow` | 影 | 影 |

`color` と `font` のみ子へ継承する。それ以外は継承しない。

> **レイアウトの上書き** (方向・配置・表示/非表示) は `EXT-018` で M2 の範囲。M1 のテーマは**見た目のみ**を変える。
> レイアウトを変えたい場合は M1 ではプラグインを使う。

## 6.1 背景画像 (`EXT-021`〜`EXT-024`)

BetterDiscord / Vencord のテーマで最も需要が大きい機能である。**M1 に含める。**

`background` は色の短縮記法に加えて、オブジェクトを受け付ける。

```jsonc
{
  "select": "app.window",
  "style": {
    "background": {
      "color": "$color.bg.base",
      "image": "assets/wallpaper.png",
      "fit": "cover",
      "position": [0.5, 0.35],
      "opacity": 1.0,
      "blur": 0,
      "tint": "#0f0f1766"
    }
  }
}
```

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `color` | 色 | 透明 | 画像の**下**に敷く色。画像が読めなかった場合のフォールバックでもある (`EXT-027`) |
| `image` | アセット参照 | — | 背景画像 ([6.3](#63-アセットの参照-ext-017)) |
| `fit` | `cover` / `contain` / `stretch` / `tile` / `none` | `cover` | 領域への合わせ方 |
| `position` | `[x, y]` (各 0.0〜1.0) | `[0.5, 0.5]` | `cover` / `contain` / `none` のときの寄せ位置 |
| `opacity` | 0.0〜1.0 | `1.0` | 画像の不透明度 |
| `blur` | 数値 (論理 px) | `0` | 画像のぼかし半径 |
| `tint` | 色 | 透明 | 画像の**上**に重ねる色。可読性の確保に使う |

合成順序は下から `color` → `image` (`opacity`, `blur` 適用済み) → `tint`。

### 6.1.1 `blur` は読み込み時に一度だけ行う (`EXT-023`)

**背景画像のぼかしは、画像を読み込んだ時点で一度だけ適用し、結果をテクスチャとしてキャッシュする。** 毎フレームぼかさない。

S1 の実測環境 (Intel HD 520) を下限基準とする以上、毎フレームの畳み込みは避ける。ぼかし半径が変わるのはテーマの再読み込み時だけなので、これで十分である。

> `EXT-025` (ノードの背後にあるものをぼかす、いわゆるすりガラス) は**別物**であり **M2**。
> あちらは背後の内容が毎フレーム変わるため、フレームごとの処理が避けられない。

### 6.1.2 半透明合成の保証 (`EXT-024`)

背景画像を敷く使い方では、その上に載る UI が半透明でなければ意味がない。

```jsonc
{ "select": "app.window",      "style": { "background": { "image": "assets/bg.png", "fit": "cover" } } },
{ "select": "nav.channel_list","style": { "background": "#16161fcc" } },
{ "select": "chat.header",     "style": { "background": "#0f0f1799" } }
```

8 桁の色 (`#RRGGBBAA`) で不透明度を指定する。レンダラは**すべてのノードで正しいアルファ合成**を行わなければならない。

> S1 で実装した SDF バッチャは既に `BlendState::ALPHA_BLENDING` で描画しており、この要件は満たせる見込みである。
> ただし**画像テクスチャの描画経路は未実装**であり、`06-renderer.md` で定義する。

### 6.1.3 どのノードにも指定できる

背景画像は `app.window` 専用ではない。**安定 ID を持つ任意のノードに指定できる。**

```jsonc
{ "select": "nav.guild_list", "style": { "background": { "image": "assets/sidebar.png", "fit": "tile" } } },
{ "select": "chat.message.avatar", "style": { "background": { "image": "assets/ring.png" } } }
```

## 6.2 使用例: 全面背景 + 半透明 UI

冒頭のスクリーンショットのような構成を作る最小の組み合わせ。

```jsonc
{
  "tokens": {
    "color.panel":  "#16161fb3",
    "color.panel.deep": "#0f0f17cc",
    "color.text.primary": "#f0f0f5"
  },
  "rules": [
    {
      "select": "app.window",
      "style": {
        "background": {
          "color": "#0f0f17",
          "image": "assets/wallpaper.png",
          "fit": "cover",
          "tint": "#0f0f1740"
        },
        "color": "$color.text.primary"
      }
    },
    { "select": "nav.guild_list",    "style": { "background": "$color.panel.deep" } },
    { "select": "nav.channel_list",  "style": { "background": "$color.panel" } },
    { "select": "chat.header",       "style": { "background": "$color.panel" } },
    { "select": "chat.input.field",  "style": { "background": "$color.panel.deep" } },
    { "select": "chat.message",      "when": { "state": "hover" }, "style": { "background": "#ffffff14" } }
  ]
}
```

**`chat.message_list` と `chat.view` に背景色を指定しない**のが要点である。指定しなければ透明のままで、`app.window` の画像が透ける。

## 6.3 アセットの参照 (`EXT-017`)

> `EXT-017` (アセットの同梱) を M2 から **M1 に前倒しした。** 背景画像はアセットなしには成立しないため。

テーマは単一の JSON ではなく**ディレクトリ**として配布できる。

```
midnight/
├─ theme.json
└─ assets/
   ├─ wallpaper.png
   └─ Inter.woff2
```

`image` と `font.family` は 3 通りの参照を受け付ける。

| 種類 | 書式 | 例 |
|---|---|---|
| **同梱アセット** | `theme.json` からの相対パス | `"assets/wallpaper.png"` |
| **データ URI** | `data:` | `"data:image/png;base64,..."` |
| **外部 URL** | `https:` のみ | `"https://cdn.example.com/bg.png"` |

**相対パスはテーマディレクトリの外へ出られない。** `../` を含む参照、絶対パス、シンボリックリンクの追跡は拒否する。

対応形式は PNG / JPEG / WebP / AVIF。アニメーションは `EXT-026` で M2。

## 6.4 外部 URL の扱い (`SEC-022`〜`SEC-025`)

> **Vencord のテーマは外部 URL を多用する。互換性のために許可するが、無条件では許可しない。**

外部から画像を取得することは、以下を意味する。

- **起動のたびに利用者の IP アドレスが画像ホストへ渡る**
- テーマ作者またはホスト運営者が、利用者の起動時刻・頻度を観測できる
- ホストが消えるとテーマが壊れる

したがってプラグインのケイパビリティモデルと**同じ仕組み**を使う。

### 6.4.1 manifest での宣言 (`SEC-022`)

```jsonc
{
  "manifest": {
    "id": "com.example.wallpaper",
    "name": "Wallpaper",
    "version": "1.0.0",
    "abi": 1,
    "remoteAssets": ["cdn.example.com", "i.imgur.com"]
  }
}
```

**宣言されていないホストへの取得は行われない。** 拒否ではなく、そもそも到達しない。

### 6.4.2 利用者の承認 (`SEC-023`)

インストール時に取得先ホストの一覧を提示し、承認を得る。

```
「Wallpaper」は以下のサイトから画像を取得します:
  ・cdn.example.com
  ・i.imgur.com

これらのサイトには、あなたが Gumicord を起動したことが伝わります。
                                        [許可しない]  [許可する]
```

承認しなければ、外部画像は読み込まれず `background.color` にフォールバックする (`EXT-027`)。**テーマの他の部分は適用される。**

### 6.4.3 取得時の制約 (`SEC-024`, `SEC-025`)

| 制約 | 内容 |
|---|---|
| 認証情報を付けない | Cookie・Authorization・Referer を送らない |
| `https` のみ | `http` は拒否 |
| キャッシュする | 一度取得したらローカルに保存し、起動のたびに再取得しない |
| サイズ上限 | 1 ファイルあたり 32MB |
| リダイレクトの制限 | 宣言済みホストの外へのリダイレクトは追わない |

> **同梱アセットを推奨する。** ドキュメントとテーマ作成ツールは、外部 URL より同梱を既定として案内する。
> 外部 URL は「Vencord から持ってきたテーマがそのまま動く」ための互換機構と位置づける。

### 6.4.4 読み込み失敗 (`EXT-027`)

| 状況 | 挙動 |
|---|---|
| ファイルがない / 取得失敗 | `background.color` にフォールバックし、設定画面に警告を出す |
| 未対応の形式 | 同上 |
| サイズ上限超過 | 同上 |
| 未承認のホスト | 同上 (エラーではなく「未承認」として表示) |

**テーマ全体を無効化しない。** 画像 1 枚が読めないだけで UI が使えなくなるのは過剰である ([7 章](#7-検証とエラー処理-ext-016) と同じ方針)。

## 7. 検証とエラー処理 (`EXT-016`)

> **要件**: もしテーマが JSON Schema に違反するならば、システムは**該当ルールのみを無視し、エラーを利用者に提示した上で残りを適用**しなければならない。

**テーマ全体を捨てない。** 1 つのルールの誤りで画面が真っ白になる、という体験を作らない。

| 誤りの種類 | 挙動 | 利用者への通知 |
|---|---|---|
| JSON として壊れている | テーマ全体を適用しない | エラー |
| `manifest` が欠けている / 不正 | テーマ全体を適用しない | エラー |
| トークンの循環参照 | 当該トークンを解決不能として扱い、参照するルールを無視 | エラー |
| 未定義のトークンを参照 | 当該**プロパティ**を無視 | エラー |
| 値の型が違う | 当該**プロパティ**を無視 | エラー |
| **未知の安定 ID** | 当該**ルール**を無視 | 警告 (エラーではない) |
| **未知のプロパティ名** | 当該**プロパティ**を無視 | 警告 (エラーではない) |
| **未知の `when` のキー** | 当該**ルール**を無視 | 警告 (エラーではない) |

### 7.1 未知のものが「警告」である理由

**前方互換性のため。** 新しいバージョンの Gumicord 向けに書かれたテーマを古いクライアントで開いたとき、知らない ID やプロパティが出てくるのは正常な状況である。

- 未知の**安定 ID** → 将来追加されたノード。無視して残りを適用するのが正しい
- 未知の**プロパティ** → 将来追加された機能。同上

エラーとして扱うと、テーマ作者は「最も古いクライアントに合わせる」ことを強いられる。それは生態系を縮ませる。

### 7.2 エラーの提示

エラーは**設定画面のテーマ一覧に、ファイル名と位置つきで**表示する。起動を妨げるダイアログは出さない。

位置の示し方は、誤りの種類によって 2 通りある。

| 誤り | 位置の示し方 | 理由 |
|---|---|---|
| JSON の構文誤り | **行番号と列番号** | パーサが位置を持っている |
| 意味の誤り (型・トークン・未知の ID など) | **JSON パス** (`rules[3].style.background.image`) | 下記 |

> **意味解析の段階では行番号を復元できない。** 値の木にした時点で位置情報が失われるためである。
> 位置を保つパーサに差し替えれば行番号も出せるが、依存を 1 つ増やす対価に見合うか未検証である。
>
> **JSON パスのほうが優れている面もある。** 編集の途中で行がずれても指し続けられ、
> `rules[3].style.background.image` は「どのルールの何が悪いのか」を行番号より直接に伝える。
> M1 はパスで進め、利用者の反応を見てから行番号の要否を判断する。

### 7.3 「何が無視されたか」を診断に含める

診断は重大度だけでなく、**無視された単位**を持つ (`テーマ全体` / `ルール` / `プロパティ` / `トークン` / `なし`)。

「エラーが 3 件あります」だけでは、テーマが使えないのか、角丸が 1 つ効いていないだけなのかが分からない。
利用者が知りたいのは重大度ではなく**影響範囲**である。

## 8. ホットリロード (`EXT-015`)

テーマファイルの変更を検知し、**再起動なしに再適用する**。

- 監視対象はテーマファイル本体と、同梱アセット (`EXT-017`, M2)
- 再適用はフレーム境界で行う
- 検証に失敗した場合、**直前に成功したテーマを維持する**。編集途中の壊れた JSON で画面が崩れないようにする

---

## 9. `EXT-020` (全プラットフォームで同一の描画結果) の限界

> **正直に記しておく。テーマの JSON が同じでも、フォントが同じとは限らない。**

`"family": "Inter"` と書いたテーマは、Inter が入っていない環境では別の書体で描画される。S2 で確認したとおり、グリフの整形はプラットフォームのフォントに依存する。

対策は 2 つあり、**M1 では前者のみ**を採る。

| 対策 | 状態 |
|---|---|
| クライアントに既定フォントを同梱し、`family` 未指定時はそれを使う | **M1** |
| テーマがフォントを同梱できるようにする (`EXT-017`) | M2 |

`NFR-015` (スクリーンショット比較による検証) は、**同梱フォントのみを使うテーマ**に対して行う。システムフォントに依存するテーマは比較対象にしない。
