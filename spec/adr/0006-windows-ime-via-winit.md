# ADR-0006: Windows のテキスト入力は `winit` の IME 経路で足りる

| | |
|---|---|
| ステータス | **承認** |
| 起票日 | 2026-08-22 |
| 決定日 | 2026-08-22 |
| 関連要件 | `PLT-001`, `PLT-002` |
| 置き換える決定 | [ADR-0005](0005-ime-strategy.md) の「Windows は TSF テキストストアを自前実装する」 |

> **[ADR-0005](0005-ime-strategy.md) を supersede する。** ADR-0005 は消さない。
> **なぜ誤ったのかが、決定そのものと同じくらい価値のある記録**だからである。

---

## 背景

ADR-0005 は、スパイク S2 で「変換候補ウィンドウが一切出ない」ことを観測し、原因を次のように結論づけた。

> TSF IME が IMM32 ブリッジで動作 → `winit` が IMM32 メッセージを握り潰す → UI が出ない。
> 利用者が普段使っている IME の UI を正しい位置に出すには、**アプリ側が TSF のテキストストア (`ITextStoreACP`) を実装する必要がある。**

この結論に基づき、P2 (TSF テキストストア) を**規模 XL・M1.1 のクリティカルパス**と位置づけた。M1.1 で唯一の XL である。

## 何が起きたか

M1.1 のテキスト入力層を実装したところ、**`winit` のまま、TSF テキストストアなしで変換候補ウィンドウが正しく出た。**

| | |
|---|---|
| OS | Windows 10 Pro 22H2 (ADR-0005 の検証機と同じ) |
| winit | 0.30 (同じ) |
| **Google 日本語入力** | ✅ 候補ウィンドウが出る。インライン変換・予測候補とも成立 |
| **Microsoft IME** | ✅ 同上 |
| ATOK | 未検証 (検証機に無い) |
| 位置 | 入力欄を避けた位置に出る。打ちすぎると隠れるが**公式 Discord も同じ挙動** |

## 原因は TSF ではなく、渡していた矩形だった

S2 も `set_ime_allowed(true)` と `set_ime_cursor_area` を呼んでいた。違いは**渡した矩形**である。

| | S2 (出なかった) | M1.1 (出た) |
|---|---|---|
| 矩形 | キャレット位置の**幅 2px** | **入力欄全体** (約 1030×54 論理 px) |

`winit` は Windows で `CANDIDATEFORM` を `dwStyle=CFS_EXCLUDE` として設定する。つまり渡した矩形は「候補ウィンドウを置く場所」ではなく、**避けるべき領域**である。

幅 2px の矩形は、IME にとって「ほぼ何も避けなくてよい」という指示になる。その状態で IME は入力欄と重なる位置に候補を出そうとし、結果として出せなかった (あるいは出しても見えなかった) と考えられる。入力欄全体を渡すと、IME はその上下どちらかへ確実に逃がせる。

S2 のコメントには最後の疑いがこう残っていた。

> 残る疑い: `set_ime_cursor_area` を呼ぶこと自体が候補ウィンドウを消している。
> winit は `CANDIDATEFORM` を `dwStyle=CFS_EXCLUDE` で設定するため、指定した矩形を避けるよう IME に指示している。

**半分当たっていた。** 呼ぶこと自体ではなく、渡す矩形が誤っていた。

> ⚠️ **S2 は「TSF ブリッジの退化した UI が二重に出る」ところまで観測している** ([ADR-0005](0005-ime-strategy.md#しかし単純な転送では解決しない-))。
> あれは `winit` をフォークして IMM32 メッセージを**転送**した場合の話であり、`set_ime_cursor_area` を正しく使う話とは別である。
> 二つの実験結果を同じ結論へまとめてしまったのが、ADR-0005 の誤りの入口だった。

## 決定

**Windows で TSF テキストストア (`ITextStoreACP`) を自前実装しない。** `winit` の `Ime` イベントと `set_ime_cursor_area` で足りる。

### 変わらないもの

**[`TextInputHost`](0005-ime-strategy.md#設計方針) の抽象は残す。** ADR-0005 のこの部分は誤っていない。

- 文書モデル ([`TextDocument`]) は OS に触らない。位置は UTF-8 のバイト位置で通す
- Windows / Android / iOS はその文書を操作する層として並ぶ
- Android の `InputConnection` と iOS の `UITextInput` は**依然として自前実装が要る** (A2 / I2)

変わったのは「Windows もその 1 つとして XL の実装を要する」という部分だけである。

### `set_ime_cursor_area` に渡すもの

**入力欄全体の矩形**を渡す。キャレットの矩形ではない。

これは `CFS_EXCLUDE` の意味からの帰結であり、**偶然そうしたら動いた設定ではない**。避けてほしい領域を渡す。

## 影響

| | ADR-0005 | ADR-0006 |
|---|---|---|
| P2 (Windows のテキスト入力) | **XL**。M1.1 のクリティカルパス | **S**。完了済み |
| M1.1 の XL の数 | 1 | **0** |
| A2 / I2 (Android / iOS) | XL・未検証 | **変わらず XL・未検証** |
| [ADR-0001](0001-native-rust-renderer.md) の見直し条件 | 「Windows TSF が 3 倍を超えたら」 | 消滅 |

**M1.2 の最大リスクは減っていない。** A2 と I2 は Windows とは別の機構であり、今回の発見は直接には効かない。ただし「テキスト入力層は自前実装が要る」という一般化された前提は弱まったので、A2 の先行調査では**まずプラットフォームの標準経路で足りないかを疑う**べきである。

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| TSF を予定どおり実装する | **要らないものを作ることになる。** XL の実装は、それ自体が保守対象になる |
| 決定を保留のまま先へ進む | 保留のまま M1.1 を終えると、P2 が本当に不要かを誰も判断しないまま残る |
| ADR-0005 を書き換える | **なぜ誤ったのかが失われる。** 誤りの経緯は次に同じ罠を踏まないための資産である |

## 引き受けるリスク

| リスク | 対処 |
|---|---|
| ATOK で動かないかもしれない | 検証機に無い。手に入ったら確かめる。動かなければ見直し条件に当たる |
| 高 DPI・複数ディスプレイで位置が壊れるかもしれない | `PLT-009` の検証で一緒に見る |
| 文節の区切り直し (Shift+←→) や再変換が成立しないかもしれない | `winit` の `Ime` イベントに情報が足りない可能性がある。使ってみて詰まったら見直す |
| `winit` の実装に依存している | `CFS_EXCLUDE` の扱いは `winit` の内部仕様である。変わったら壊れる。上流に張り付いておく |

## 見直し条件

以下のいずれかが起きたら、TSF テキストストアの自前実装へ戻る。

- **ATOK で候補ウィンドウが出ない**と分かったとき
- 文節の区切り直しまたは再変換が `winit` の `Ime` イベントでは成立しないと分かったとき
- 高 DPI・複数ディスプレイで候補ウィンドウの位置が実用にならないとき
- `winit` が `CFS_EXCLUDE` の扱いを変え、候補ウィンドウが出なくなったとき

## 教訓

**「原因はこれだ」と結論づけた時点で、その原因を取り除かずに現象が消えないかを試すべきだった。**

ADR-0005 は 5 つの仮説を潰し、6 つ目に辿り着いた。手続きとしては正しい。しかし最後の 1 つ (`set_ime_cursor_area` に渡す矩形) は、**S2 のコメントに疑いとして書かれていながら試されないまま**、結論が確定した。

疑いを書き残したこと自体は良かった。**書き残した疑いを潰さずに ADR を承認したのが誤りだった。**
