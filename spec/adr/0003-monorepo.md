# ADR-0003: 単一のモノレポで開発する

| | |
|---|---|
| ステータス | 承認 |
| 決定日 | 2026-08-14 |
| 関連要件 | `EXT-002`, `EXT-003`, `EXT-005`, `NFR-014`, `NFR-015` |

## 背景

プロジェクト開始時点で `gumicord/Android`, `gumicord/iOS`, `nennneko5787/desktop` の 3 リポジトリが存在した (いずれも README と LICENSE のみ)。これはプラットフォームごとに実装を分ける前提の構成である。

しかし [ADR-0001](0001-native-rust-renderer.md) でレンダラを単一の Rust 実装にすると決めたため、**プラットフォームごとに分ける実装がそもそも存在しない**。プラットフォーム固有なのは各アプリのエントリポイントと OS 統合の薄い層だけになる。

## 決定

**すべてを単一のモノレポに統合する。既存の 3 リポジトリはアーカイブする。**

```
gumicord/
├─ spec/       仕様 — 単一の真実の源
├─ core/       Rust — Gateway / REST / Store / UITree / QuickJS ホスト
├─ render/     Rust — wgpu レンダラ、プラットフォーム統合
├─ app/        Rust — 各プラットフォームのエントリポイント
│  ├─ desktop/    Windows / macOS / Linux
│  ├─ android/    Gradle + NDK ラッパ
│  └─ ios/        Xcode ラッパ
├─ sdk/        TypeScript — プラグイン SDK (型定義 + CLI)
└─ examples/   公式サンプルのテーマとプラグイン
```

## 理由

### 1. 拡張 ABI の同期ズレを構造的に防ぐ

`EXT-003` は「安定 ID に破壊的変更を加えない」ことを要求する。この保証には、**UITree の定義・レンダラの実装・SDK の型定義・適合テストが常に同一のコミットで一貫している**必要がある。

リポジトリを分けると、`core` が新しいノードを追加したのに `sdk` の `.d.ts` が古い、という状態が容易に発生する。モノレポなら CI が単一のコミットに対して整合性を検査できる。

### 2. 全プラットフォーム同一性の検証が CI で回る

`NFR-015` は「同一の UITree とテーマから生成された描画結果をスクリーンショット比較で検証する」ことを要求する。この検証は全プラットフォームのビルドが同一コミットから生成されて初めて意味を持つ。

### 3. 仕様駆動開発と相性がよい

仕様変更 → 実装 → SDK → テストの更新が 1 つの PR に収まる。「仕様は更新されたが実装が追いついていない」状態がレビュー時点で可視化される。

### 4. 分ける理由が実際にない

分割の一般的な動機は「独立したリリースサイクル」「独立したチーム」「ビルド時間」だが、いずれも該当しない。全プラットフォームは同一バージョンで足並みを揃えてリリースする必要がある (`EXT-043`)。

## 検討した代替案

### A. 既存 3 リポジトリを維持し、`core` と `spec` を追加

- ○ 既存の GitHub 構成を壊さない
- × 5 リポジトリのバージョン同期が必要になる
- × `spec` を submodule で共有する運用は、submodule の更新忘れという新しい失敗モードを生む
- × **単一レンダラである以上、プラットフォーム別リポジトリの中身がほぼ空になる**

### B. spec のみ先に独立したリポジトリとして作る

- ○ 仕様に集中できる
- × 結局あとで統合するなら、最初から統合しておくほうが移行コストがない

## 帰結

### 移行作業

| 対象 | 措置 |
|---|---|
| `gumicord/Android` | GitHub 上でアーカイブ。README に移行先を記載 |
| `gumicord/iOS` | 同上 |
| `nennneko5787/desktop` | 同上。なお remote が `gumicord` org を向いていない設定ミスがあったが、アーカイブするため修正不要 |
| ローカルの `android/`, `desktop/`, `iOS/` | 移行完了まで `.gitignore` で除外。完了後に削除 |

### ビルド

- Rust 部分は Cargo workspace で管理する
- `app/android` は Gradle、`app/ios` は Xcode プロジェクトだが、いずれも Rust ライブラリを取り込むだけの薄いラッパに留める
- SDK は pnpm workspace で管理する
- **ルートに単一のタスクランナーを置く** (`just` または `cargo xtask`)。プラットフォームごとにビルド手順を覚える必要をなくす

### CI

モノレポなので変更パスに応じたジョブの出し分けが必要になる。

| 変更パス | 実行するジョブ |
|---|---|
| `spec/schema/**` | JSON Schema の検証、SDK 型定義との整合性検査 |
| `spec/03-uitree.md` | 安定 ID の後方互換性検査 (`EXT-003`) |
| `core/**`, `render/**` | Rust のテスト、全プラットフォームのビルド |
| `sdk/**` | 型検査、SDK のテスト |
| 上記いずれか | 描画結果のスクリーンショット比較 (`NFR-015`) |
