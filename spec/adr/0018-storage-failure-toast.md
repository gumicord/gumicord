# ADR-0018: 保存できないことを利用者へ伝える手段

| | |
|---|---|
| ステータス | **承認** |
| 起票日 | 2026-10-24 |
| 関連要件 | `FR-003`, `FR-007` |
| 前提となる決定 | [ADR-0007](0007-login-paths-and-captcha.md) (トークンはセキュアストレージにしか置かない) |
| 関連仕様 | [01-requirements.md](../01-requirements.md) `FR-007`、[03-uitree.md](../03-uitree.md) `overlay.toast` |

---

## 背景

`FR-003` はトークンを OS のセキュアストレージに置くことを求め、
「暗号化できない環境では保存しない」は守られている。
守られているからこそ、守った結果が**利用者に見えない**。

失敗は 2 か所で起きるが、いずれも `tracing::warn` に落ちて画面へは届かない:

1. **起動時** — `SecretStore::new()` が失敗し、ストアが丸ごと無くなる
2. **ログイン後** — ストアはあるが書き込みが拒否される。Linux で Secret
   Service デーモンが無い場合がこれで、`load` は「無い」と返し `remember`
   が失敗する

結果として、利用者は**理由を知らぬまま毎回ログインし直される**。
`FR-007` はこれを黙っていなくする要件である。

あわせて `notify_toast` には「User-initiated outcomes only」という既存の
制約がある (理由は chatter while the user reads)。起動時の失敗は利用者の
操作の結果ではないため、この制約との関係を先に決める必要があった。

## 決定

`overlay.toast` で知らせる (`FR-007`)。メッセージは **1 つの文字列**として
書き、`format!` で組み立てない ([ADR-0010](0010-i18n-by-message-ids.md) の語順の制約)。

| いつ | 担い手 |
|---|---|
| 起動時にストアが無かった | `Login::start_with_restore` がフラグを立てる |
| ログイン成立後に書き込みが失敗 | `remember_account` が `LoginEvent::StorageFailed` を送る |

アプリは毎フレーム `Login::take_storage_failed()` で抜き取り、
`notify_toast` へ渡す。抜き取りは `take_last_error` と同じ one-shot の形である。

### 制約との関係

チャタリングしないのは **起動 1 回、および新規ログイン 1 回ごとに 1 件**で
あり、既存の制約が禁じている「読み手を待たせながら散らかる」状態には
入らない。よって起動時の失敗もトーストでよい。

`store` が無くてログインしたとき (上の 1 を起動時に告げ済みの状態) は
**再度告げない**。同じ起因に 2 度鳴るのは、かえって散らかるため。

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| モーダル (`PendingDialog::notice`) | 成功したログインを一度止め、「わかった」が毎回押しになる。保存の欠落はログインの妨げではない |
| ログイン画面の `set_notice` | `notice` はログイン成功とともに消える (`a_notice_leads_until_signing_in_succeeds`)。しかし書き込みの失敗は**ログイン成功後に**判明するため、経路が繋がらない。止めるには起動時に鍵束へ到達可否を確かめる新 API が要り、platform 層への追加が大きい |
| 設定画面への常設表示 | 見る場所が固定され、ログインし直している利用者がそこへ寄る理由が無い。トーストだけで足りる範囲に対し変更が広い |
| 読み取り不能 (`load` 失敗) の合算 | `FR-003` の方針が「読めないなら毎回ログインでよい」であり、要件を足さずに同じ文で包めない。今回は保存側に限る |

## 引き受けるリスク

| リスク | 対処 |
|---|---|
| 数秒で消えるため見逃される | 伝えたいのは「次回も入力が要る」という結果であり、その事実は次回の起動で再現する。消えたあとでも体験が裏切らない |
| トーストが 3 件で古いものから落ちる | 保存失敗の通知は起動・ログインごとに 1 件であり、他と積み合わない場面でしか出さない |
