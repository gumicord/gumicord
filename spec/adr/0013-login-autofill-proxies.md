# ADR-0013: ログインの自動入力のため不可視プロキシを残す

| | |
|---|---|
| ステータス | **承認** |
| 起票日 | 2026-09-18 |
| 決定日 | 2026-09-18 |
| 関連要件 | `FR-001`, `PLT-040` |
| 関連 | [ADR-0011](0011-mobile-input-bridges.md) の一部を置換 |

---

## 背景

[ADR-0011](0011-mobile-input-bridges.md) はログインフィールドの不可視プロキシを廃止し、
全欄を隠し `UITextInput` エディタに一本化した。理由は性能だった
（表示中ずっと毎フレーム `request_redraw` するビジースピン）。

実機 (iOS) で試すと、単独エディタではパスワードマネージャがメール欄・
パスワード欄の片方ずつしか埋めないことが分かった。エディタは
フォーカスのある欄の `textContentType` に切り替わるため、
階層内に username 欄と password 欄が同時に存在しない。
ペア補完には両欄の同居が要る。

## 決定

**ログインのメール・パスワード欄にだけ、不可視 `UITextField` 双子を戻す。**
それ以外の欄は隠しエディタのままである。

| | |
|---|---|
| 対象 | ログインのメール欄・パスワード欄のみ |
| 仕掛け | `username`＋`password` の隠し双子。両方を貼り付けたままにし、片方の補完が両文書へ届く |
| 駆動 | フォーカス中のペース再描画に相乗りするポーリング。独自フレームは回さない（廃止理由のスピンは再発させない） |
| 破棄 | フォーカス喪失・送信が決まったそのイベントで resign する。次の再描画までキーボードを残さない |

## 却下した選択肢

| | なぜ却下したか |
|---|---|
| 隠しエディタの2枚化 (自前 `UITextInput` を2枚貼る) | 自作ビューのペア補完が実機で成立するか未検証。文書化された経路 (`UITextField` 双子) を取る |
| 単独エディタのまま `textContentType` の付け替えで粘る | 1つのビューは1つの内容種別しか持てず、ペアの前提が満たせない |

## 引き受けるリスク

| リスク | 対処 |
|---|---|
| 不可視ビューの細工が残り続ける | ログイン2欄に限定。ほかの欄はエディタのまま |
| プロキシとエディタが first responder を奪い合う | プロキシが有効な間はエディタを blur し、`winit` の IME も落とす |
| OS の更新でペア条件が変わる | 実機で補完から確認する。壊れたら本 ADR ごと見直す |

## 見直し条件

- 自前エディタだけでもペア補完が成立すると実機で確認できたとき → プロキシを再廃止する
- OS 側により良い自動入力口が来たとき → そちらへ移す
