# ADR-0010: 多言語対応は文言 ID の表引きで行う

| | |
|---|---|
| ステータス | 提案 |
| 決定日 | 未定 |
| 関連要件 | なし (M1.1 の対象外。設定画面の文言が増えたため先に方針だけ決める) |

## 背景

画面に出る文言は日本語で直書きしている (NEXT.md §4 の決定)。設定画面で利用者向け文言がさらに増えた (`plugin_state_label`、`capability_bullets`、分類名、空状態の説明)。英語対応を後付けで始めると、文言の置き場所が散らばり、同じ権限が場所によって別名になる。

## 決定

いずれ多言語対応するときは、**文言 ID を鍵とする表引き**で行い、対応までは直書きのまま足す。gettext 式の原文キー (`_("有効")`) は選ばない。原文が変わると全言語の鍵が変わり、UITree の安定 ID と同じ壊れ方をするためである。

## 表引きが守るべき制約

実装時まで持ち越す約束。現在の実装はすべて満たしている。

- 操作の特定に表示文字列を使わない。行は `Key::Index`、窓のボタンは番号、固定の選択肢は `Key::Slot` で指す (設定画面も同じ)。
- 利用者向けの名付けは一箇所に置く。権限名は `capability_bullets`、状態名は `plugin_state_label` が唯一の出所であり、言語が増えても出所は増やさない。
- プラグインの設定頁の文言はプラグイン側の責任である。ホストは表を通さずそのまま載せる。
- 日付・時刻・相対表示は現地化の対象であり、文言表とは別の層 (`app/core/src/time.rs` 側) で扱う。

## 対象外

- 対応言語の選定と既定言語 (直書きが日本語であることだけが事実)。
- 表ファイルの形式と置き場所、切替 UI (設定画面の分類が増える)。
- プラグイン向けの文言 API (設定イベント配送と一緒に設計する)。
