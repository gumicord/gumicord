# ADR-0014: モバイルのスクロール追従と起動スプラッシュ

## 背景

実機で 2 つの症状が出た。

| 症状 | 原因 |
|---|---|
| 指を払っても惰性スクロールが始まらない・すぐ止まる | `FLING_MIN = 120px/s` が Android 標準 (`ViewConfiguration.MINIMUM_FLING_VELOCITY = 50dips/s`) の 2 倍以上で、ゆっくりめのフリックが捨てられる。`FLING_TAU = 0.12s` も短く惰性がすぐ消える |
| スクロールバーのつまみを掴めない | スクロールバーのノードはポインタのホバーがあるときだけ生える (`hovered_scroll`)。タッチにはホバーがないため、モバイルではスクロールバー自体が存在せず、掴みようがない |
| 起動時にログイン画面が一瞬出てからサーバー一覧に切り替わる | 保存トークンからの復帰中 (`Session::Connecting`)、キャッシュがないとログイン画面の骨格が約 1 秒表示され、`Done` でメインへ切り替わる。Discord モバイル版はこの間スプラッシュを出す |

## 決定

### フリングは Android 標準に寄せる

| 定数 | 変更前 | 変更後 | 根拠 |
|---|---|---|---|
| `FLING_MIN` | 120px/s | 50px/s | Android の下限と同値。論理ピクセル≒dip として直読する |
| `FLING_TAU` | 0.12s | 0.25s | 惰性が体感で続く長さ。Discord / Telegram 相当の余韻を狙う |
| `FLING_STOP` | 40px/s | 据え置き | 停止閾値は変えない |
| `FLING_MAX` | 6000px/s | 据え置き | テレポート抑止の上限であり体感に効かない |
| `FLING_DIST_MIN` | 96px | 据え置き | 低速の長い drag の救済は維持する |
| `TAP_SLOP` / `SWIPE_MIN` | 据え置き | — | タップ側を緩めると誤タップが増える。今回の不満は惰性とつまみであり触らない |

### スクロールバーはモバイルで常時出す

- デスクトップは従来どおりホバーがある一覧だけに出す。
- モバイル (`is_mobile()`) ではホバーなしで全一覧に出す。はみ出しがない一覧には出ない (レイアウトが `over <= 0` を置かないため)。
- 指先では幅 10px の軌道が狙えないため、タッチの掴み判定だけ左右に 12px 広げる。マウスの判定は変えない。
- 指を置いたときに軌道の上なら即座に掴み、長押しメニュー・指スクロール・フリング計測は始めない。離したら掴みを放すだけで、タップとしてもスワイプとしても扱わない。

### 起動スプラッシュは UITree 内に出す

- `Session` が起動直後 (`booting`: 初回の確定イベントが未到達) で、キャッシュもログインもない間、`login_screen()` の代わりに `AppScreenLoading` を出す。
- ネイティブの起動画面 (Android SplashScreen API / iOS LaunchScreen) は作らない。UITree 内だけで起動から一貫して描画する。
- 新しい安定 ID は足さない。`app.screen.loading` は ABI に既にあり、中身は既存の `primitive.text` で組む。
- キャッシュがある起動は従来どおり即メイン (C6 の先行描画を崩さない)。

### 却下した選択肢

| | なぜ却下したか |
|---|---|
| タップ側 (`TAP_SLOP` 拡大、`SWIPE_MIN` 縮小) の緩和 | 誤タップ・誤返信が増える。実機計測なしに触る場所ではない |
| タイマーでスクロールバーを消す方式 | イベントループは `Wait` するため消灯タイマーの管理が要る。常時表示で問題が出たらそのとき検討する |
| ネイティブ起動画面の追加 | 殻ごとの実装が 3 つ要る (Android / iOS / デスクトップ)。UITree 内で足りる |
| スプラッシュ用の新安定 ID | `app.screen.loading` が未使用のまま残っている。追加は ABI を広げるだけで要らない |

## 見直し条件

- 実機で惰性が長すぎる・短すぎるとの報告があれば `FLING_TAU` を再調整する。
- つまみの誤掴み (本文スクロールのつもりが掴みになる) が多ければ、掴み余白 12px を縮める。
- 常時スクロールバーが見た目の妨げになるとの報告があれば、操作時表示＋消灯への切替えを検討する (v0.2.0 の UI 棚卸しと一緒に)。
