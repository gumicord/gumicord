# ADR-0009: macOS / Linux デスクトップを M1 へ前倒しする

| | |
|---|---|
| ステータス | **承認** |
| 起票日 | 2026-08-30 |
| 関連要件 | `EXT-043` (プロジェクトの根本命題), `PLT-046` / `FR-044` 等のデスクトップ別要件 |
| 置き換える決定 | [07-roadmap.md 7 章](../07-roadmap.md#7-m2-以降の概要) の「macOS / Linux は M2」 |

---

## 背景

[07-roadmap.md](../07-roadmap.md) は長らく「macOS と Linux は M2」とし、次の根拠を載せていた:

> macOS と Linux が M2 なのは、M1 で証明すべきことが「デスクトップとモバイルで拡張が同じに
> 動く」だからである。デスクトップを 3 つ揃えても、その命題は 1 ミリも進まない。

これは**製品スコープの論理**であり、それ自体は今も正しい。しかし同時に、M2 へ据え置く理由の
背後には「デスクトップを 3 つ揃えたことが無く、macOS / Linux がそもそもビルドできるか・動くか
が未知数」という**技術リスク**も潜んでいた。この部分は今回の実測で解消した。

## 何が起きたか / 何を調べたか

**CI (`dist`) ジョブを macOS / Linux / Windows の 3 台で走らせ、`gumicord-desktop` の
実行バイナリが 3 つとも生成できることを実測で確認した** (2026-08-30)。

デスクトップの 3 つは Windows / macOS / Linux で同一の `winit` + `wgpu` (desktop) スタックを
共有している。ビルドは既に通る:

- `render/render/src/gpu.rs` — バックエンド分岐 (Windows=GL+DX12, macOS=METAL, その他=VULKAN+GL)
  が OS ごとにコンパイル・選択される。
- `core/theme/src/cond.rs` — テーマ層は既に 5 プラットフォームを列挙済み。
- `render/platform/src/url.rs` — リンク開放は `xdg-open` (`open`) で macOS / Linux に対応済み。
- `core/store/src/db.rs` — POSIX のロック競合によるハングを `busy_timeout` と writer スレッドの
  join で解消済み。

つまり「デスクトップを揃えたことが無い」という技術的な未知はなくなり、macOS / Linux を
M1 に含めることが**実測ベースで安全**になった。

## 決定

**macOS / Linux デスクトップを M1 に含める。** 具体的には [07-roadmap.md](../07-roadmap.md) の
M1.2「横に広げる」を「Android / iOS **と macOS / Linux デスクトップ**」へ広げる。

- M1.1「縦に通す」は**引き続き Windows のみのフェーズゲート**のまま。アーキテクチャ全体が
  成立するかを 1 プラットフォームで確かめる段階であり、ここは変えない。
- M1.2 では、モバイル 2 つ (Android / iOS) に加えて**デスクトップ 2 つ (macOS / Linux) を**同じ
  テーマ・同じプラグインで動かすことを検証する。
- macOS / Linux はデスクトップ共通スタックを持つため、Windows の実装を横に持っていく作業
  (I/D 系統) は Android / iOS よりもコストが小さい見込みである。この見込みは実測で確認しながら
  進める (ADR ルール 4「推測で決めない」)。

M2 からは「macOS / Linux」の項目を除き、デスクトップ 3 つは M1 で揃える。

## 代替案 (却下)

| 案 | 却下理由 |
|---|---|
| **M2 のまま維持** (記録のみ) | 技術リスクが解消した以上、M2 へ据え置く唯一の根拠が「製品スコープの論理」だけになり、デスクトップ 3 つを揃える作業を M1 の実測から外す損が上回る。デスクトップの IME・アクセシビリティ (accesskit) の差異は M1 で早く拾いたい。ユーザーが「M1 に前倒し」を選択 |
| **M1 と M2 の間に macOS / Linux 評価フェーズを新設** | マイルストーンを増やす価値が、デスクトップ 3 つが同一スタックである事実に比べて弱い。M1.2 の「横に広げる」に含めるほうが自然 |

## 影響

- [07-roadmap.md](../07-roadmap.md) を改定する:
  - M1.2 の定義 (2.2)、スコープ (2.1)、成功判定のプラットフォーム表記
  - M1.2 の作業分解 (6 章) に macOS / Linux デスクトップの作業を追加
  - 最大リスク (6.1) に macOS / Linux の注意を追記
  - M2 (7 章) から macOS / Linux を除き、根拠を更新
- 実行時の健全性 (IME 含む) の確認は**テスター任せ**のままであり、CI のビルド成功を以て
  「動作確認済み」にはしない。
